# YM2149 SID-Voice（软件 PWM）— 检测与抚平研究笔记

> 2026-10-21 · 探究性记录（暂不集成）· 样本：`Bullet Sequence.vgm`（Atari ST, YM2149 @2005311Hz, 3.8MB）

## 1. 现象与数据

Atari ST 高频中断驱动 YM2149 的 "SID voice" 技法：CPU 高速重写音量寄存器 R8-R10，
芯片的 4 位 DAC 输出在听觉上变成**连续的软件 PWM**——不是断续的方波台阶。

Bullet Sequence 实测（脚本见本文末尾思路）：

| 指标 | 数值 |
|---|---|
| 平均写入速率 | 4462 写/秒 |
| 写入分布 | 88% 是 R8/R9/R10（音量），R0-R5 各仅 ~50 写/秒（正常旋律） |
| R8 写入间隔中位数 | 18 采样 = **408µs ≈ 2.4kHz** |
| 写入值分布 | 0-15 近乎均匀，0/9/14/15 有峰（占空比在扫） |

## 2. 原理（对照 psg-core/libvgm）

psg-core（`ay8910.c`）对 R8-10 的处理就是**锁存直读**：
每个采样周期输出 `ay_volume[ch] & 0x0F`。没有任何特判——
PWM 的"连续感"来自：调制率（2-8kHz）写值变化 + 输出谱=均值+边带 + 人耳低通。
即模拟器里效果自然涌现，事件式转换器却只看到离散写 → 逐写发事件 = 拉链噪声。

## 3. 检测算法（便宜且可靠）

按声道维护滚动窗口（vtime 驱动，20ms）：
- `ampWrites[ch]`：窗口内 R8+ch 的写入次数；
- **进入 PWM 模式**：窗口写入率 > ~500Hz（即间隔中位 < 2ms，远低于 Bullet 的 2.4kHz）；
- **退出**：连续 2 个窗口 < 100Hz（滞回防抖动）。
- 可选加强判据：窗口内写入值方差高（占空比在扫）而音调周期稳定。

## 4. 抚平算法（已数值验证）

- PWM 模式下，**忽略逐写幅度事件**（消除事件风暴——这是顺带的大收益：
  这类曲子 88% 的事件是音量写，抚平后事件量降一个数量级）；
- 每 20-30ms 发一次**窗口均值**换算的电平（0-15 均值 → ×8.5 → 0-127），
  走现有 CC7/volFollow 链；
- 音高照旧取音调周期（这类曲子 R0-R5 就是正常旋律线）。
- 数值验证：Bullet ch0 的 20ms 均值曲线平滑（相邻窗差中位 1.1 / 15 满量程），
  且呈现作曲家刻意做的周期性幅度调制（9↔14 循环）。

## 5. "音色切换"效果

PWM 段的听感（连续、有扫描感）与普通方波截然不同。映射建议：
- 进入 PWM 模式 → 该声道 GM 音色切到持续性强的 patch
  （30=失真吉他 / 81=主音锯齿 / 62=铜管），退出时切回方波默认 80；
- 音色切换点复用现有 `buzzProgSent` 机制（换音色前 buzzOffAll 防挂音）；
- 这就再现了"方波→连续音色"的切换感，和蜂鸣器语义笔记
  （docs/TONERT_HANDOFF.md §8）是同族现象：芯片边界用法=音色表达。

## 6. 集成点（若将来要做）

Ay2Midi.write() case 8/9/10：
```java
if (pwmMode[ch]) { pwmSum[ch] += (v & 0xF); pwmCnt[ch]++; return; }  // 不发事件
updateChannelCtl(ch);  // 正常路径
```
tick()/定时点（20ms 窗）：`if (pwmCnt>阈值) v = pwmSum/pwmCnt; 发电平事件`。
内存：每声道 3 个 int，可忽略。大文件（3.8MB vgm）对单缓冲流无压力
（抚平后事件密度反而比普通曲子低）。

## 7. 结论

- 检测便宜（滚动计数+滞回），抚平有效（数值已验），音色切换有现成机制；
- 不集成的理由只有"这类曲子少且文件大"；哪天要支持，按 §3-§6 直接做。
